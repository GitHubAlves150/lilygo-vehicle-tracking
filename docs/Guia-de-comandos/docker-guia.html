Desinstalação Completa

PASSO 0
Parar todos os containers
docker stop $(docker ps -aq) 2>/dev/null
Remover todos os containers
docker rm $(docker ps -aq) 2>/dev/null
Remover todas as imagens
docker rmi $(docker images -q) 2>/dev/null
Remover todos os volumes
docker volume rm $(docker volume ls -q) 2>/dev/null
Limpeza geral do sistema
docker system prune -a --volumes -f 2>/dev/null
Atenção: Os comandos acima ignoram erros (2>/dev/null). Execute apenas se tiver containers/volumes.
Remover Docker Desktop
sudo apt remove --purge docker-desktop -y
Remover configurações do usuário
rm -rf ~/.docker/desktop ~/.docker/config.json
Remover binários
sudo rm -f /usr/local/bin/com.docker.cli /usr/local/bin/docker-compose
Remover Docker Engine (se instalado)
sudo apt remove --purge docker-ce docker-ce-cli containerd.io docker-compose-plugin -y sudo apt remove --purge docker.io docker-compose -y sudo rm -f /etc/apt/sources.list.d/docker.list sudo rm -f /etc/apt/keyrings/docker.gpg sudo groupdel docker 2>/dev/null
Remover pastas residuais
sudo rm -rf /var/lib/docker /var/lib/containerd /etc/docker ~/.docker sudo rm -f /var/run/docker.sock ~/.docker/desktop/docker.sock
Verificar se tudo foi removido
which docker # Deve retornar vazio docker --version # Deve dar "comando não encontrado"
Sistema limpo! Agora você pode prosseguir com a instalação do Docker Engine.

Instalação do Docker Engine

PASSO 1
Atualizar pacotes
sudo apt update
Instalar dependências
sudo apt install -y ca-certificates curl gnupg lsb-release
Adicionar chave GPG oficial
sudo mkdir -p /etc/apt/keyrings curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
Adicionar repositório
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
Instalar Docker Engine
sudo apt update sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
Dica: O Docker Compose agora é integrado como plugin. Use docker compose (com espaço), não docker-compose (com hífen).

Configuração Inicial

PASSO 2
Adicionar usuário ao grupo docker
sudo usermod -aG docker $USER
✅ Permite rodar docker sem sudo (é necessário re-login ou reiniciar).
Ativar serviço do Docker
sudo systemctl enable docker && sudo systemctl start docker
Testar hello world
docker run hello-world
Se aparecer "Hello from Docker!", a instalação está perfeita.
Verificar status
sudo systemctl status docker
Pronto! Docker instalado e configurado. Agora você pode rodar containers sem sudo.

Docker Compose (Projetos)

PASSO 3
Construir imagem
docker compose build
Lê o Dockerfile e cria a imagem do seu projeto.
Subir container (detached)
docker compose up -d
Cria e inicia o container em background.
Parar e remover
docker compose down
Para os containers e remove redes/volumes criados.
Executar comando dentro do container
docker exec -it lilygo-vehicle-tracking bash
Abre um shell interativo dentro do container.
Baixar/construir e rodar
docker compose up -d --build

Gerenciamento de Containers

COMANDOS DIA A DIA
Listar containers rodando
docker ps
Listar TODOS containers
docker ps -a
Iniciar container parado
docker start <nome>
Parar container rodando
docker stop <nome>
Remover container
docker rm <nome>
Limpar containers parados
docker container prune

Imagens e Volumes

ESPELHOS E DADOS
Listar imagens baixadas
docker images
Listar volumes
docker volume ls
Construir imagem manualmente
docker build -t <nome> .
Baixar imagem do Docker Hub
docker pull ubuntu:22.04
Remover imagem não usada
docker rmi <nome>
Limpeza geral: docker system prune -a --volumes remove tudo que não está em uso.

Logs e Diagnóstico

MONITORAMENTO
Ver logs do container
docker logs lilygo-vehicle-tracking
Acompanhar logs em tempo real
docker logs -f lilygo-vehicle-tracking
Ver recursos do container
docker stats
Inspecionar container
docker inspect <nome>
Porta USB não aparece no container? Verifique a permissão: sudo chmod 666 /dev/ttyACM0 e confira se o devices no docker-compose.yml está apontando para a porta correta.
